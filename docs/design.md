# 数字猫桌面宠物 — 设计规格

> 日期：2026-06-01 | 状态：已确认，待实现

## 一、产品定义

将用户家中的真实猫变成 Windows 桌面上的"数字生命"——一只有 AI 驱动的模拟养成型桌面宠物。

### 目标猫

- **品种**：中华田园奶牛猫（黑白色）
- **特征**：黑色身体，白色胸部，白色肚皮，四只白色爪子（白手套），鼻梁至额头有白色火焰纹
- **眼**：黄褐色
- **体型**：成年猫，中等体型，体态匀称

### 核心约束
- **不说话**：猫以行为而非语言互动
- **像真猫**：Disney/皮克斯风格的偏真实 2D 动画，有猫毛细节
- **有记忆**：AI 驱动行为，有别于脚本写死的电子宠物

## 三、素材管线

### AI 参考图规范

AI 视频生成前，先为每段视频生成对应动作姿态的参考图，作为视频的首帧输入。参考图质量直接决定视频质量。

| 要素 | 要求 | 理由 |
|------|------|------|
| 背景色 | 中等亮绿色 `#00E676`（非荧光绿 `#00FF00`） | 奶牛猫黑白两色毛均不含绿色分量，跟绿幕完全不撞色 |
| 画幅比 | 16:9 横向 | 走路时身体+尾巴水平伸展幅度大，横向空间是纵向的 1.78 倍 |
| 分辨率 | 1920×1080 | 16:9 标准分辨率，AI 工具原生支持 |
| 帧率 | 24fps | Disney 动画标准帧率，AI 视频工具以此输出 |
| 编码 | MP4 / H.264 | 标准输入格式 |
| 猫高度 | 画面高度的 **50%**（~540px） | 正面站立时足够呈现毛发细节，不大不小 |
| 猫垂直位置 | 脚底在画面 **85%** 处（距顶 918px） | 猫站在地面，上方留 378px（猫高×0.7）跳跃伸展空间 |
| 下方绿幕 | 162px（15%） | 保证猫脚与地面分离，BiRefNet 边缘识别不打折扣 |
| 风格一致性 | 8 张参考图使用同一提示词模板 | 猫的毛发纹路、耳朵形状、眼睛颜色保持一致，只换动作描述 |

### 灯光规范

抠图后猫贴在桌面上，灯光必须模拟**室内环境光**——没有特定方向偏倚，否则猫永远看起来"被某个方向的光照着"，跟桌面不搭。

```
         ☁ 柔光箱（主光）
         ▼ 上方 45°，亮度 ~70%
         
  🐱  ← 猫
         
         ▲ 反光板（补光）
           下方 15°，亮度 ~30%
```

| 参数 | 设置 | 理由 |
|------|------|------|
| 主光 | 上方 45° 大面积柔光箱，亮度 ~70% | 模拟室内天花灯/窗外自然光，猫毛从顶部自然提亮 |
| 补光 | 下方 15° 弱反光板，亮度 ~30% | 消除下巴/胸腹部的死黑阴影，但不破坏体积感 |
| 光影比 | 约 2:1（主光:补光） | 有立体感但不戏剧化，猫毛层次可见 |
| 禁用 | 侧光、轮廓光、逆光、硬光 | 侧光→抠图后猫半边亮半边暗，无法适配不同桌面壁纸 |

**对抠图的意义：** 猫毛边缘是一层自然的柔光过渡，BiRefNet 抠出的 alpha 通道边缘干净，不会出现暗边或色溢。成品贴在深色壁纸和浅色壁纸上都不违和。

### 参考图生成工作流

```
1. AI 生图（Midjourney/DALL-E）
   输入统一提示词模板，产出 8 张参考图
   → 相同猫的外观特征，不同动作姿态
   → 全部中等亮绿色背景

2. 参考图 → AI 视频（可灵/Runway）
   每张参考图作为对应视频的首帧
   → 绿色背景贯穿全视频

3. BiRefNet (rembg) 逐帧抠图
   → erode_size=1 保留软边缘 → despill 去除绿幕颜色溢出
   → 成品 RGBA PNG，毛发细节保留，边缘自然过渡

4. deploy_sprites.py 部署精灵图
   → 逐帧猫身体对齐 → 尺寸匹配 → 统一宽高 → DyberPet JSON 配置绑定
```

### 统一提示词模板

所有参考图和视频 prompt 共用此猫的外观描述，仅替换动作部分：

> 一只中华田园奶牛猫，黑色身体，白色胸部，白色肚皮，四只白色爪子（白手套），鼻梁至额头有白色火焰纹，黄褐色眼睛。中等体型，体态匀称，猫毛细节可见。Disney/皮克斯动画风格。纯绿色背景（#00E676）。
> 
> 猫站在画面下方，四只脚踩在地面上，脚底距画面顶部约 85% 位置，脚底以下到画面底边留约 15% 空白区域。猫从脚底到头顶约占画面高度一半。

### 视频规格定稿

| 参数 | 值 |
|------|----|
| 画幅比 | 16:9（横向） |
| 分辨率 | 1920×1080 |
| 帧率 | 24fps |
| 编码 | MP4 / H.264 |
| 猫高度 | 540px（画面 50%） |
| 猫脚底距顶 | 918px（85%） |
| 下方绿幕 | 162px（15%） |
| 上方可用 | 378px（35% ≈ 猫高×0.7） |

### 镜像原则

**不做任何镜像/翻转。** 所有需要双向的动作（向左走、向右走）均独立生成 AI 视频。避免翻转导致的尾巴左右错位、光影方向不一致等问题。

## 四、动画架构

### 中枢姿态：正面站立

所有动画从同一只猫的**正面站立姿态**（Neutral Pose）出发并返回。正面站立不区分左右朝向，无论猫在屏幕左侧还是右侧，待机姿态一致，避免了左右镜像问题。

每条 AI 视频 prompt 的首尾帧都用相同的正面站立姿态描述，首尾帧天然接近，衔接自然。

### 生成策略：能合就合，时长兜不住才拆

| 策略 | 适用条件 | 示例 |
|------|---------|------|
| **一段视频生成** | 总时长 ≤ 10 秒 | 走路（正面→侧走→正面 = 8s），伸懒腰（正面→伸→正面 = 6s） |
| **拆成多段生成** | 总时长 > 10 秒 | 睡觉（正面→蜷→睡→起→正面 = 18s），拆成 3 段 |

一段视频生成后，后期在时间轴上切分成"进入过渡 / 循环段 / 退出过渡"三个精灵序列。同源视频的角色一致性天然有保证。

### ping-pong 播放

需要循环的动画段正向+反向播放。反向末帧 = 正向首帧，天然无缝，素材时长翻倍。不需要 AI 生成的视频本身首尾一致。

### 动画状态机

```
                    ┌── [动作5: 向左走] ──────────┐
                    │  正面→转左侧→侧走(循环)      │
                    │  →停止→转回正面              │
                    │                             │
                    ├── [动作6: 向右走] ──────────┤
                    │  正面→转右侧→侧走(循环)      │
                    │  →停止→转回正面              │
                    │                             │
    [动作0: 待机] ──┤                             │
      正面站立姿态   │                             │
                    ├── [动作1-4: 抓取→落地] ─────┤
                    │  1: 抓取(正面→被拎悬垂)       │
                    │  2: 悬挂(悬垂,循环)           │
                    │  3: 下落(四肢张开,ping-pong)  │
                    │  4: 落地(着地→站起)           │
                    │                             │
                    ├── [动作7: 入睡] ────────────┤
                    │  正面→蜷缩→闭眼侧卧          │
                    │                             │
                    ├── [动作8: 睡梦中] ──────────┤
                    │  蜷缩睡觉(循环)              │
                    │                             │
                    ├── [动作9: 醒来] ────────────┤
                    │  睁眼→伸展→站起              │
                    │                             │
                    └── [后期追加] ───────────────┘
                        被摸/吃东西/伸懒腰/发呆
```

### 首尾帧衔接规范

不同视频段之间通过保持首尾帧 prompt 描述完全一致来保证衔接：

| 衔接点 | 统一描述 |
|--------|---------|
| 中枢姿态 | **"正面站立，四条腿直立，眼睛半睁看着前方"** |
| 睡眠姿态 | **"蜷缩闭眼，侧卧，前爪收拢"** |

同一句话在相关视频的 prompt 首尾出现，AI 倾向生成视觉接近的画面。微小差异靠 2-3 帧 blending（~100ms）掩盖。

### 走路方向选择逻辑

运行时根据猫在屏幕上的位置决定播放哪个视频：

```
猫在屏幕右侧
  └── 往左走 → 直接播放"向左走"
  猫在屏幕左侧 
  └── 往右走 → 直接播放"向右走"
  
```

## 六、养成系统（基于 DyberPet 已有系统调整）

| 数值 | 范围 | 衰减速度 | 影响 |
|------|------|---------|------|
| 饱食度（HP） | 0-100 | -1/分钟 | Tier 0（Starving）时好感度每分钟 -5 并可降级 |
| 好感度（FV） | 0-∞（按等级） | +1/分钟（自然增长） | 解锁动画、控制气泡行为 |

### HP Tiers
`[0, 20, 70, 100]` → Starving / Hungry / Normal / Energetic

### FV 等级
lv0 升级需 20 点，lv1+ 每级 120 点。HP tier 0 时 FV 每分钟 -5，降到 0 后触发降级（如 lv4→lv3 满值 120）。

### 互动手段
- 喂食：消耗食物道具，+HP
- 点击猫：+金币（高斯分布），25% 概率触发自娱自乐动画
- 物品掉落：亲密度越高掉落概率越大（基础 8%，每级 +2%，上限 25%）

## 七、AI 行为引擎设计

### 输入
- 当前时间（几点）
- 猫的状态（养成数值）
- 近期互动历史（过去 1 小时）
- 性格参数（固定种子值）

### 处理
- 每 1-5 分钟调用一次决策函数
- Ollama 可用 → `qwen2.5:3b` 推理输出行为决策 JSON
- Ollama 不可用 → `scripted_fallback` 规则引擎自动降级（夜晚睡觉、饥饿等食、活跃边缘走动）
- 决策通过 `queue.Queue` + DyberPet 主线程 QTimer 轮询消费，推送到动画系统
- 猫的性格参数首次启动随机生成，持久化到 SQLite `cat_personality` 表，后续启动恢复

### 输出
- 告诉 DyberPet 播放哪个动画
- 告诉 DyberPet 移动到哪个位置
- 触发气泡提示（如"猫饿了..."），countdown 类型气泡支持鼠标靠近自动隐藏

### 性格参数（每只猫唯一）
- 活跃度（懒猫<->好动）
- 黏人度（独立<->黏人）
- 贪吃度
- 好奇心
